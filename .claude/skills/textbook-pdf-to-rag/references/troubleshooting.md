# 故障排除：現象 → 原因 → 處理

先找到對應的那一列，只修出問題的那一段，修好後從那一段接著跑。
同一個問題處理第二次還沒好，就停下來向使用者說明看到什麼、試過什麼。

## 0–1 切分與 OCR
| 現象 | 原因 | 處理 |
|---|---|---|
| `找不到 mineru-kit` | 沒裝或不在預期路徑 | 用 `--mineru-kit` 指定；沒裝就依 01 安裝（先徵得同意） |
| 單份逾時 | 頁數太多或 GPU 被占用 | 用 `--redo` 單獨重跑；常發生就把每份頁數調小（要重切，先問） |
| CUDA out of memory | 同時有其他程式用 GPU（例如 Ollama 載著模型） | 停掉其他 GPU 程式後 `--redo` |
| 公式裡 δ 不見、`>` 變 `≥` | 用了 PDF 文字層 | 確認 `--ocr-mode ocr` |
| 切分時說「已有切好的 PDF」 | 保護機制：那些檔可能已 OCR | 確認真要重切才加 `--force`，並告知 Markdown 會對不上 |
| 已有輸出卻沒被略過、或被覆蓋 | 檔名含 `[ ]` 等 glob 特殊字元 | 腳本已用 `glob.escape`；自己寫的腳本也要注意 |

## 2 清理
| 現象 | 原因 | 處理 |
|---|---|---|
| 某條規則觸發次數遠超預期 | 樣式太寬，刪到正確內容 | 收窄樣式；必要時從 `backup/` 還原再跑 |
| 再跑一次 dry-run 還有修改 | 規則不冪等（取代結果又被匹配） | 加邊界條件，例如 `(?![A-Za-z])` |
| 受保護檔案出現在「會觸發」清單 | 正常：保護機制不改它 | 請使用者決定是否手動套用 |
| Markdown 每份都有很大的 base64 | 還沒清理 | 跑第 2 段 |
| 真的表格被換成圖片佔位 | 表格很稀疏，達到「空表格」門檻 | 從 `backup/` 取回該檔的表格手動貼回，並列入 `protected_files` |

## 3 字型
| 現象 | 原因 | 處理 |
|---|---|---|
| 抽不到任何小標題 | 字型名稱或 `after` 條件不符；掃描版 PDF 沒文字層 | `inspect_fonts.py --find` 查實際字型；掃描版就跳過這段 |
| 小標題數量多到不合理 | 把例題結尾符號、定理框標題也算進去 | 加 `after` 條件或限定字型家族，並記下易混淆的字型 |

## 4 切塊
| 現象 | 原因 | 處理 |
|---|---|---|
| 章節數少於目錄 | OCR 吃掉編號，且目錄沒解析到或標題對不上 | 看輸出的「目錄 N 節」；檢查 `toc_entry`；比對該節開頭的實際標題 |
| 一大段被算到錯的章節 | 交互參照或同名小標題被當成章節開頭 | 看「順序不合理」清單與該處 Markdown；依目錄順序與「不跳過有編號章節」規則通常可解 |
| 附錄內容出現在最後一章 | 沒偵測到附錄開頭 | 設定 `appendix_start`、`appendix_toc_entry` |
| 例題很長、包含下一段觀念說明 | 例題結尾沒有標記，下一個小標題沒被認出 | 補小標題字型提示（第 3 段）或 `subheading_line` |
| 例題缺解答比例高 | `solution_marker` 寫法不符，或例題被提早切斷 | 抽查缺解答的例題 id |
| 習題混進觀念說明 | 「Exercises」標籤被吃掉 | 用題號字型提示（`exercise_item` + `with_next`） |
| 驗證報告章節順序倒退 | 星號章節、附錄（已排除），或真的切錯 | 看報告列出的 id 前後兩塊 |
| 重複內容警告 | 書本身重複（替代章節），或同一頁被 OCR 兩次 | 看是否來自不同 source_files |
| `$$` 不成對 | 公式被切斷，或 OCR 本身漏了一個 `$$` | 看該塊的 source_spans；OCR 漏的就手動修 Markdown 並列入保護 |
| 改了一處設定，別處壞了 | 規則互相影響（例：排除小標題後，章節本身的標題也被排除） | 每次改動都比較整體章節集合與每節例題數（04 的比較腳本） |
| `1.1.1` 這類編號小節被當成新章節 | 預設 `section_heading` 接受三層編號 | 設定只接受兩層（加 `(?![.\d])`），三層改用 `subheading_line` 當子主題；範例見 kurose 設定檔 |
| 章概述不見，或被併進上一章最後一節 | 章標題沒被認出（不是單一個 `#`） | 依實際格式設定 `chapter_heading`；看輸出的「章導論 N 塊」是否等於章數 |
| 框的內容混進觀念說明，或一句話被框切斷 | 沒有設定 `sidebar_heading` | 依「可能是側欄的全大寫標題」清單設定，只寫框名 |
| 一般小標題被當成框 | `sidebar_heading` 寫得太寬（例如所有全大寫） | 只列實際的框名；這個欄位區分大小寫 |
| 不相關的兩段被接在一起 | 斷句判斷誤判（少見，例如網址小寫開頭） | 抽查輸出的接回數；必要時把 `join_broken_paragraphs` 設成 false |

## 5 片段與向量
| 現象 | 原因 | 處理 |
|---|---|---|
| 片段超過 2048 token | 單一公式或表格本身就超長 | 少量可接受（會被截斷）；大量時檢查是否有 OCR 垃圾表格 |
| `無法連線 Ollama` | 服務沒開 | `ollama serve`；`ollama pull <模型>`（先問） |
| 向量庫有兩份資料 | 舊腳本用 add 而非重建，或 collection 名稱不同 | 用 `build_vector_db.py`（會重建）；舊 collection 刪掉或忽略 |
| 英文查詢也命中不相關章節 | 查詢端沒加 `search_query: ` 前綴（nomic-embed-text） | 查詢前加前綴；collection 的 metadata 記錄了該加什麼 |
| 中文問題找錯章節 | embedding 模型只懂英文 | 查詢前翻成英文檢索詞，或換多語言模型 |
| 翻譯後檢索詞帶了解法（例如自動加上 L'Hospital） | 翻譯提示詞太鬆，模型替學生猜方法 | 提示詞要求只翻譯原文，不加入方法、定理或書名 |
| 檢索到教材但回答像沒看到 | LLM context 窗口太小，教材被截掉 | 設定 `num_ctx`，並限制送入的教材總 token 數 |
| Chroma 寫入時 metadata 錯誤 | 值是 None 或 list | 只寫非空純量（腳本已處理）；自己加欄位時也要遵守 |
