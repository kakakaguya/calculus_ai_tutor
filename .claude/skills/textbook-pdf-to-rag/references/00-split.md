# 0 切分 PDF

## 為什麼要切
MinerU 一次處理整本書容易逾時或爆記憶體，失敗時也得整本重來。切成小份後，
每份獨立轉換、失敗只重跑那一份，中斷了也能接續。5 頁一份在 8 GB GPU 上約 3 分鐘。

## 要先和使用者確認的事
- **哪些頁不要。** 封面、版權頁、前言、索引、解答通常不需要。習題頁要不要留，
  取決於用途：只做觀念問答可以去掉（習題沒有解答，檢索到反而誤導）；
  要出練習題就留下。問使用者，不要自己決定。
- **目錄頁要留。** 切塊時要用目錄找回 OCR 漏掉的章節編號（見 04-chunking.md）。
- PDF 頁碼（從 1 開始數的實體頁）和書上印的頁碼通常不同。用 PDF 閱讀器的頁碼。

## 執行
```bash
.venv-mineru/bin/python $S/split_pdf.py raw/book.pdf --out pdf_split \
    --pages-per-part 5 --exclude 1-14,1180-1205 --dry-run
# 計畫正確後拿掉 --dry-run
```
- 一份不會跨過被排除的頁：排除了第 3 頁，1-5 會切成 [1,2] 與 [4,5]，每份都是連續頁。
- `split_manifest.json` 記錄每份對應的原書頁碼，之後要在回答裡標頁碼時用得到。
- 輸出資料夾已有切好的檔案時會拒絕寫入，因為那些檔案可能已經 OCR 過；
  確認要重切才加 `--force`。重切會改變檔名與頁碼對應，已有的 Markdown 就對不上了。

## 已經有切好的檔案
使用者可能用其他工具切過（例如檔名像 `Book_merged-12.pdf`）。直接沿用，
沒有 manifest 就在報告裡註明「頁碼對應未知」，不要為了補 manifest 重切。
